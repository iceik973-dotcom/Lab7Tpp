# Негативний самоконтроль

Навмисна помилка для експерименту: у `src/ODETask.cpp` замінити `trajectory_.swap(next);` на `trajectory_ = next;` **не є надійним негативним прикладом**, бо переміщення/присвоєння може зберігати гарантію. Натомість перед початком циклу `solve()` додати `trajectory_.clear();` — це порушить сильну гарантію, бо під час винятку старий результат буде втрачено.

Тест `Strong.FailedSolvePreservesOldResults` перевіряє, що після `InvalidDerivativeException` старий результат залишається незмінним. З помилкою він має завершитися невдало (доступ до `back()` порожнього вектора некоректний, тому для негативного запуску спершу перевіряти `ASSERT_FALSE(t.trajectory().empty())`). Після експерименту видалити помилковий `clear()` і повторно запустити тести. У фінальному коді помилки немає.
